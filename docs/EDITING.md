# 映像で説明するための編集手順

エフェクトを増やす前に、何を見れば分かるのかを決める。根拠は [SOURCES.md](SOURCES.md)。そこにある推奨は一般原則であり、全作品共通の秒数テンプレートではない。

## 1. 見せられる疑問を選ぶ

冒頭の実写一枚で「何が起きている？」が伝わる題材にする。挨拶、ロゴ、タイトルカードから始めない。答えを引っ張るだけにせず、小さな発見を途中にも置く。説明は一つの問いに絞り、因果と具体例で終点へ進む。図がないと成立しない説明は、撮影・記録素材を探すか、問いを具体化する。

手元に適切な参考Shortsがあれば、画面サイズ・主役の大きさ・最初に見える動作・画の切り替わる理由・声のない瞬間・最後の回収を短く観察する。視聴していない作品を評価対象にしない。再生数は題材や配信条件にも左右されるため、編集の証明とは別に扱う。

## 2. 素材の中から選ぶ

一次映像、撮影素材、信頼できるストックを探す。検索語の一致ではなく、人物・機体・時代・動作の一致を見る。遠景、動作、細部という異なる情報を持った画をそろえる。

`tools/selects.py` でシーン境界と時刻付きの画像一覧を作り、候補を元映像でも確認する。PySceneDetectは切り替え候補を作るだけで、説明に合う画や「いい瞬間」は判断しない。黒画面、スレート、焼き込み文字、既存の編集点を避ける。採用区間の頭・中・末尾を確認する。

## 3. 声を作り、カットを置く

短い意味のまとまりをlineにする。声の抑揚、読み、息継ぎを整えてから実尺を得る。単語数による擬似的な音声時間は使わない。録音済みナレーションも同じ工程で扱う。

新しい対象が出る瞬間、動作が完了する前、答えが見える瞬間にカットを検討する。言葉に先行して画を見せたり、画の前に音を聞かせたりする。shots/audioは同じグローバル時間軸を使い、別beatのlineも参照できる。これでJ/Lカットと音の橋渡しを行う。

広い画から細部へ、動作から結果へなど、画が変わると情報も増えるようにする。単純な一定間隔カットを避け、見せる動作には時間を与える。連続する動作を別アングルへつなぐ時は、動作の段階と画面内の向きを合わせる。

## 4. 縦画面を構図として作る

中央切り抜きを放置しない。cameraのx/yは素材中の主役の位置、zoomはcoverを基準にした倍率。必要なら最初と最後の位置を変えて主役を追う。元映像に動きがあるならカメラ演出は静止のままでもよい。

主役の頭・手・重要な動作を切らない。右端の操作ボタンや下端のアプリUIで重要部分が隠れないよう、主役を余裕のある位置へ置く。見せる情報が横に分かれている場合は別ショットを探すか、意図してcontainを使う。低解像度を拡大して品質が上がったと扱わない。

## 5. 音でつなぐ

声、現場音、音楽を別々に選ぶ。元映像の音を使う時もaudioに明示して、映像の切れ目に縛られずつなぐ。現場音は実際の出来事を伝える重要な材料。SEで事実を誤認させない。

音楽は必要な作品にだけ。発話中はduckを使い、意味のある無言の瞬間に戻す。カットをまたぐ環境音と短いフェードで接続する。耳に痛い音、音源ごとの音量差を確認する。FFmpegの2パスloudnormで全体を約−16 LUFS／true peak −1.5 dB目標に整える。これはこのエンジンの運用値で、YouTubeの必須値ではない。

## 6. 意味から演出を選ぶ

カットと音声が成立してから、`project.json.editing.events`へ演出を置く。最初は「主張を強調する」「現物を見せる」「一瞬止めて確認させる」など、必要な判断だけを記す。`pattern`は技法の組み合わせ、`reason`はその場面で使う理由。`intent`、`emotion`、`importance`は任意の意味情報として残せる。詳しい指定は [EDITING_CONTRACT.md](EDITING_CONTRACT.md)。

- 原文の重要語: `emphasize_claim` / `numeric_fact`。語が見える字幕ページで短く使い、全語を強調しない。
- 実際の対象を見せる: `show_evidence` / `broll_cutaway`。B-rollの素材・対象・時代が発話に合うか確認する。
- 意外性や説明の停止: `comic_interrupt` / `freeze_frame`。停止後も同じ動画から進み、音声は独立して続く。
- 視線の移動: `shift_focus`。calloutは必要な説明に限り、標準の実写作品へ機械的に追加しない。
- 動作でつなぐ: `momentum_transition`。前後素材の余白と向きを見て使う。v1ではwhipと速度変更は同じ前後ショットに置けない。

発話参照を優先し、音声の長さが変わっても判断を追従させる。AivisSpeechの比例字幕は単語の実測時刻ではない。強勢や語への厳密な同期が必要なら、試聴してoffsetを調整するか、実測文字時刻を取り込む。自動で「驚き」を認識して配置する分類器は持たない。編集判断はCodexが行う。

全画面演出は字幕を巻き込んで揺らさない。パンチズームはオーバーシュートから収束し、収束倍率はショット末尾まで保持する。短いSEは演出の一部として、その着地や衝撃へ配置する。同一パターンを展開するたびにSEを重複生成しない。密度の助言が出たら前後を見直し、必要なものだけ残す。

## 7. 完成映像で直す

reviewで各ショットの最初・中央・最後を並べる。音付きで全体を再生し、気になったカットの前後をinspectで短く取り出す。冒頭の理解、音と画の意味、主役の見切れ、カットの飛び、声の自然さ、最後の回収を確かめる。

弱ければ、まず台本の削減・別テイク・source_start・カット位置・構図・音を直す。問題が素材の中身ならアニメーションでは埋められない。手直しはproject.jsonへ戻す。完成版で全文デコード、解像度、実尺、fps、48kHz、実測ラウドネスを確認する。

reviewにはショットの3点に加え、演出の直前・同期点・末尾・直後、理由、SEの同期時刻が並ぶ。「前後を音付き再生」で動きと音のつながりを見る。エンジン変更は同一原稿のA/Bも確認する。字幕の衝突、未知の技法、素材不足、実際には不透明な切り抜き、壊れた出力は止める。冷却時間・強い演出の回数は助言であり、創作上の合否にはしない。
