# 指示とスキルの見直し

2026-09-18。対象はこのリポジトリのAGENTS.md、制作・開発手順、同梱Remotionスキルの入口。

根拠はOpenAIの[Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)。必要な作業だけにスキルを適用し、参照を段階的に読み、承認の境界と依頼の完了条件を明確にする、という助言を適用した。

## 判断と変更

| 確認した問題 | 変更 |
| --- | --- |
| どの作業でも最初に編集手順を読む指示 | AGENTS.mdに用途別の参照表。制作・音・演出・CLI・Remotion開発で入口を分けた |
| スキルのdescriptionが「全Remotionスキルへのルーター」で、適用する作業が不明 | コンポーネント・レンダー・依存関係の実装／不具合修正に限定した説明 |
| 新しい動画の依頼を常に汎用Create手順へ送る | 通常の案件は既存project.jsonとCLIへ。Createは別Remotionプロジェクトなどを明示依頼された場合に限定 |
| Create参照のStudio終了点・追加レンダー依頼が、既存制作の完了条件と競合 | スキル入口に、依頼済みの制作・検証にはリポジトリの承認範囲と完了条件を適用すると明記 |
| READMEの検証コマンド一覧と編集手順のA/Bが全変更に適用されうる | 変更別の検証選択を追加。画・音が変わる場合に実レンダーとA/Bを使う |
| 背景buildの起動後・再開時の到達点が曖昧 | 正本とstatusを確認し、依頼範囲に応じてfinal検証・納品のAPI確認まで進める |

制作時だけ必要な詳細は[編集手順](EDITING.md)に集約した。初回制作承認、正本、実写中心、同一原稿の全文字幕、素材・音・透過の検証、YouTubeの納品／公開境界、サブエージェント禁止は維持する。CLI、レンダー実装、依存バージョン、利用者全体のCodex設定は今回の変更対象にしていない。

## 依頼例による文書レビュー

以下は指示を読み合わせた結果であり、別エージェントを動かした行動評価ではない。

| 依頼例 | 確認した経路・終了点 |
| --- | --- |
| READMEの誤字を直す | 該当文書の修正と参照確認。映像制作資料や実レンダーを一律に要求しない |
| 新しい解説Shortsを作る | 制作案を正本へ残して提示し、素材取得・音声生成の前に初回承認 |
| 新しいShortsを確認不要で最後まで完成させる | 既存エンジンでpreview・視聴・修正・final検証まで。納品も依頼されていればその確認まで |
| 承認済み動画の字幕を修正する | 同じ正本を編集して再生成・確認。別プロジェクト作成や再承認を要求しない |
| Remotionの字幕描画を直す | スキルの字幕／Markupと該当API。型・対象テストに加え、表示を実レンダーで確認 |
| 演出のGPU処理を検証する | 演出契約と該当fixture。未対応処理を省いて成功扱いにせず、fixtureを投稿しない |
| 進捗だけ教える | statusの確認と報告で完了。制作の再開は含めない |
| YouTubeへ非公開納品する／公開する | 依頼された範囲のdeliver／publishを使い、APIから状態を再取得 |

## 検証記録

- skill-creatorの`quick_validate.py`に成功。UIメタデータ、アイコン参照、同梱スキルのバージョンとRemotion 4.0.521の一致も確認した。
- 変更した5つのMarkdown文書のローカルリンク29件を確認し、ファイルと参照見出しの欠落はなかった。
- `video.py`、`selects.py`、`review_server.py`の`--help`が成功。`catalog`と`catalog --schema`がJSONを返すことを実行確認し、status遷移とreview出力パスを実装と照合した。
- 既存の制作要件を変更前と比較し、移動した詳細の参照先まで確認した。上記8例は文書レビュー済み。
- AGENTS.mdは2,064→1,778文字、スキル入口は2,483→2,169文字。LFに正規化した本文の文字数であり、トークン計測ではない。
- 今回は指示・文書の変更なので映像の再レンダーは対象外。文書レビューだけでモデルの行動改善、動画の芸術的品質、コンテキストのトークン削減量を実証したとは扱わない。

Remotionスキルを更新する時は、ローカルの入口とUIメタデータの差分を確認し、上記の依頼例で汎用Create手順への誤誘導が戻っていないか見直す。
